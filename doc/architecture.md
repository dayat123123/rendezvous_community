# Arsitektur `rendezvous_community`

> Dipindahkan dari README package (1.0.0). Cara pakai ada di [README package](../README.md) dan [docs/INTEGRATION.md](https://github.com/dayat123123/chat_service_supabase/blob/main/docs/INTEGRATION.md).

Clean Architecture **per fitur**. Setiap fitur berdiri sendiri dengan tiga lapisan:

```
lib/src/
  app/        RendezvousCommunity (titik komposisi: merakit repository, DeliveryTracker,
              ClientConfigService, CommunityAnalytics, siklus hidup aplikasi),
              CommunityDependencies (kontrak DI), CommunityScope + CommunityNavigator,
              CommunitySupportScope, CommunityAccountScope (dokumen hukum & akun),
              CommunityFeatureScope + CommunityFeatureDependencies (fitur 1.3.0)
  core/       infrastruktur tanpa UI: auth (TokenManager, auth-bridge, identitas host), error, logging,
              network (data source Supabase + RPC anonim, media gateway, gateway & status realtime,
              CommunityConnectivity, SharedStream, helper JSON), paging, parser $KODE/@mention/#hashtag/tautan,
              MIME gambar, storage (OfflineCache per user, OfflineStore drift/memori, CommunityDatabase)
  shared/     entitas bersama (UserSummary, Attachment), model JSON bersama,
              kit UI (tema, lokalisasi ARB, avatar, state view, SocialText, composer)
  features/
    feed/          stream & feed, kartu post         chat/          daftar & room chat, centang, mengetik
    post/          detail post & thread komentar      poll/          polling: entitas, vote, CommunityPollView
    compose/       composer post + editor polling     notifications/ notifikasi & badge
    profile/       profil user                        stocks/        halaman saham & watchlist
    moderation/    laporan & blokir                   media/         unggah & tampilkan lampiran
    legal/         dokumen hukum, persetujuan, banner account/       ekspor data, hapus akun, "Privasi & akun"
    config/        konfigurasi klien, kill switch     search/        pencarian, feed hashtag, hashtag trending
    trending/      trending & sentimen saham          bookmarks/     bookmark & daftar simpanan
    edit/          edit post/komentar                 message_requests/ permintaan DM & kebijakan DM
    appeals/       banding & sanksi                   link_preview/  kartu & loader link preview
    analytics/     pencatat event (track_events)   offline/       banner offline (presentasi saja)
    drafts/        draf postingan (lokal + server)
      domain/        entitas immutable (freezed), kontrak repository, layanan domain
      data/          model JSON (freezed + json_serializable), implementasi repository
      presentation/  cubit/ (flutter_bloc), widgets/, dan builders/ (kontrak builder UI: chat, feed, notifications, profile;
                     badge dan detail status daftar di shared/presentation/builders, agregat CommunityBuilders di app/)
```

Aturan dependensi:
- `core` tidak bergantung pada apa pun di package.
- `shared` hanya bergantung pada `core` (kecuali widget yang butuh navigasi lewat `CommunityScope`).
- Fitur boleh memakai **domain** fitur lain (mis. `compose` memakai `poll/domain`), tidak pernah lapisan `data`-nya. Pengecualian: model baris kontrak server yang dipakai bersama (`FeedPostModel` untuk `feed_post`, `ThreadCommentModel` untuk `thread_comment`, `ChatMessageModel` untuk `chat_message`, `HashtagSummaryModel`) boleh dipakai lapisan data fitur lain yang RPC-nya mengembalikan baris yang sama (search, bookmarks, edit, trending, chat extras), seperti `support` memakai model chat.
- `app` adalah satu-satunya tempat yang mengenal semua implementasi.
- Cubit selalu di file sendiri (`presentation/cubit/`), terpisah dari widget.
- Widget chat bawaan dan builder kustom memakai `details` yang sama. Logika (handler) dibuat sekali di widget pengendali, lalu tampilan bawaan (`_Default*`) maupun builder host hanya menggambarnya.
- Hal yang sama berlaku untuk feed, kartu post, komentar, polling, notifikasi, profil, dan badge (1.4.0). Setiap set builder punya `of(context)`, `merge` (semua field; dicek `test/tool/merge_completeness_test.dart`), scope InheritedWidget, dan helper `with*Builders`. `CommunityBuildersScope` menggabungkan kelima set dengan scope di atasnya; `carryCommunityBuilders` membawanya ke route yang dibuka package.
- **Gambar (1.4.0):** `CommunityImageProvider` (shared) memuat byte lewat `CommunityImageLoader` (cache disk → `source()` → HTTP) lalu mendekode dengan `getTargetSize` (cover, kelipatan 64 px, maks 2048 px). Kunci memori = (kunci stabil, ukuran target). Cache disk `ImageDiskCache` (core/storage): `FileImageDiskCache` di `dart:io` (file `<sha256>-<ms dibuat>` per user, indeks di memori dari listing folder, LRU byte, kedaluwarsa dari nama file, tulis lewat file `.tmp` lalu rename, generasi untuk membuang tulisan yang kalah balapan dengan `wipe`), `NoImageDiskCache` di web atau bila `offlineCache: false`. `RendezvousCommunity` memanggil `images.wipe()` di `signOut`/`deleteMyAccount`/`clearLocalCache` dan saat user sesi berganti; pemilik folder = `currentUserId` atau pemilik database offline (buka offline).
- Import di dalam package memakai `package:rendezvous_community/...` (lint `always_use_package_imports`).
- Kode tanpa komentar; penjelasan ada di dokumen ini dan di `docs/rendezvous-community/`. CI menolak komentar baru (`tool/check_comments.dart`), kecuali `// ignore:` dan file hasil generate.
- Library tidak mencetak ke konsol; semua log lewat `CommunityLoggers` ([logging.md](logging.md)). CI menolak `print`/`debugPrint` di luar modul logging (`tool/check_logging.dart`).

- **Auth:** `SupabaseClient(accessToken: tokenManager.accessToken)`.
  - JWT diperbarui otomatis 60 detik sebelum kedaluwarsa dan didorong ke koneksi realtime (`realtime.setAuth`).
  - Request yang ditolak karena JWT kedaluwarsa diulang sekali setelah refresh.
- **Error:** semua API melempar `CommunityException` dengan `kind` (`rateLimited`, `contentBlocked`, `forbidden`, …). `message` hanya untuk log/debug (Bahasa Inggris atau pesan server), tidak pernah ditampilkan langsung.
  - `code` berisi kode stabil dari server, misalnya `rate_limited`.
  - UI menampilkan pesan terlokalisasi lewat `context.communityL10n.errorMessage(e)`.
- **Realtime:**
  - `postgres_changes` (tunduk RLS) hanya untuk post, komentar, dan notifikasi. Pesan chat dikirim database lewat Broadcast ke topik privat (`0098`, [docs/social](https://github.com/dayat123123/chat_service_supabase/blob/main/docs/social/README.md#pengiriman-pesan-realtime-0098)): event `message` di `room:<id>`, dan aktivitas room (`room_activity`) di `user:<id>` milik sendiri. Aktivitas dibagi lewat `SharedStream` (satu channel untuk daftar chat dan `DeliveryTracker`).
  - Satu channel private `room:<id>` per room, dikelola `RoomChannelHub` dengan *ref-count*: daftar chat dan room yang sedang dibuka memakai channel yang sama (Phoenix menutup join ganda ke topic yang sama). Isinya hanya event dari **server**: `message`, `message_hidden`, `typing` (dikirim lewat RPC `send_typing`, identitas dari JWT), `receipt`, `reaction`, `room_state`, serta presence (siapa yang online di room itu). Klien tidak bisa mengirim broadcast ke topik ini; policy `realtime.messages` hanya mengizinkan presence. Event dengan `room_id` lain diabaikan.
  - Mengisi celah ([docs/social](https://github.com/dayat123123/chat_service_supabase/blob/main/docs/social/README.md#mengisi-celah), `0103`):
    - `ChatRoomCubit` menyimpan **horizon** (`GapHorizon`): `(created_at, id)` terbaru yang dikonfirmasi server lewat halaman pertama, `_reloadLatest`, atau gap-fill sebelumnya yang selesai. Pesan dari Realtime tidak memajukannya, sehingga lubang di tengah aliran (event dibuang batas tenant atau saat Realtime start ulang) tetap tertambal.
    - Algoritmanya di domain `MessageGapFill`: baca maju dari `horizon − gapOverlap` (bawaan 10 detik, tidak lebih tua dari pesan tertua yang dimuat), maksimal `maxGapPages` (5) halaman, lalu horizon maju ke baris terbaru yang dibaca. Repository yang juga mengimplementasikan `MessageIndexRepository` (`ChatRepositoryImpl`) memakai `get_message_ids` (hanya id, 1.000 per halaman) dan mengambil yang belum ada lewat `get_messages_by_ids` (100 per panggilan). Repository lain (chat CS) memakai `get_messages(p_after)` per 100. Melebihi anggaran → muat ulang dari pesan terbaru.
    - Penjadwalan di `GapFillSchedule`: join pertama langsung; sambung ulang setelah jeda acak `0..reconnectJitter` (5 detik) lalu sekali lagi `gapRecheckDelay..2×gapRecheckDelay` (5–10 detik) kemudian; berkala `gapFillInterval` (45 detik) × 0,75–1,25 acak per putaran; resume aplikasi (`CommunityConnectivity.resumes`) langsung. `Random` bisa diinjeksi (`ChatRoomCubit(random:)`) untuk tes.
    - Duplikat digabung lewat `id`/`client_id`. Pesan dari pengirim yang terlibat blokir datang sebagai referensi dan diambil lewat `get_messages`.
  - Daftar chat memantau maksimal 30 room DM/grup terbaru. Room saham tidak dipantau (terlalu ramai).
  - Pratinjau room (`last_message_*` di `get_my_rooms`) untuk DM, grup, dan CS diperbarui dalam transaksi pesan. Room saham tidak lagi mengantre di kunci baris `chat_rooms` (`0102`): pengirim yang mendapati baris sedang dikunci melewatinya dan mencatat room ke `private.room_preview_queue`, lalu worker pg_cron `chat-room-preview` memulihkannya ke pesan terlihat terbaru tiap ±1 detik. Pratinjau room saham yang ramai bisa tertinggal sampai ±1 detik dan tidak pernah mundur. Klien tidak perlu berubah.
- **Centang (tanda terima):**
  - Selama aplikasi terbuka dan sesi aktif, `DeliveryTracker` (dijalankan `RendezvousCommunity`) memanggil RPC `mark_rooms_delivered` saat ada pesan masuk dari orang lain. Membuka room memanggil `mark_room_read`.
  - Kedua RPC menyimpan penanda di `chat_members` lalu menyiarkan `receipt` ke `room:<id>` lewat `realtime.send` di database. Klien tidak bisa memalsukan tanda terima orang lain.
  - Status per pesan dihitung fungsi domain `receiptStatus(sentAt, penerima)`. `get_my_rooms` mengembalikan `last_message_status` untuk pesan terakhir milik sendiri.
  - Broadcast yang terlewat saat channel `room:<id>` terputus diambil ulang ketika tersambung lagi: room memuat ulang `get_room_members` (digabung, tanda terima tidak pernah mundur), daftar chat memuat ulang `get_my_rooms`.
  - Broadcast dari database butuh Realtime dengan `REGION` yang sama dengan region tenant (`us-east-1`, lihat `docker/compose.yml`). Bila berbeda, Realtime memutus koneksi DB tenant tiap 10 menit dan tanda terima hilang tanpa error.
  - Matikan pelacakan terkirim dengan `RendezvousCommunity.initialize(trackDelivery: false)` bila host punya mekanisme sendiri.
- **Badge chat:** `CommunityChatBadge` memanggil RPC `get_unread_chat_count` dan memuat ulang (digabung 1,2 detik) saat ada notifikasi baru untuk user (server membuat notifikasi `message` hanya untuk DM/grup yang tidak dibisukan, jadi room saham yang ramai tidak memicu permintaan) dan saat room dibaca, dibisukan, atau ditinggalkan di perangkat ini.
- **Polling:** dibuat bersama post dalam satu transaksi (`create_post` dengan `p_poll`), dipilih lewat `vote_poll`. Jumlah suara hanya keluar lewat proyeksi feed (`feed_post.poll`); tabel suara tidak bisa dibaca langsung oleh client.
- **Unggahan (media gateway):** `SocialRemoteDataSource.upload` mengirim byte ke `POST {supabaseUrl}/media/v1/object/{bucket}/{path}` lewat `MediaGatewayClient` (`core/network/media_gateway.dart`) dengan `apikey`, `Authorization: Bearer <JWT sosial>`, dan `Content-Type`; `x-upsert: true` hanya untuk avatar. Layanan `media` memeriksa jenis dari isi file, membuang metadata, lalu meneruskan ke Storage dengan klaim `media_verified` (kebijakan Storage menolak unggahan nasabah tanpa klaim itu). Repository memakai `path`/`mime` dari respons karena ekstensi bisa diganti. 401 → refresh sesi dan satu kali ulang. Error `{code, message}` dipetakan `mapMediaError` (status → `CommunityErrorKind`, `code` dari server); 404 tanpa kode (backend tanpa `/media/v1`) menjadi `unavailable`/`media_unavailable`. Membaca lampiran tetap lewat Storage (`authenticated`/signed URL).
- **Dokumen hukum & persetujuan:** `CommunityConsent` (`legal/domain/services`) menyimpan hasil `get_legal_documents` per sesi. `RendezvousCommunity` memanggil `onUserChanged` dari `sessionChanges`: ganti user → cache dikosongkan dan dimuat sekali; refresh token user yang sama tidak memicu permintaan. Gagal memuat → coba lagi paling cepat 30 detik kemudian. `accept` memanggil `accept_legal_document` per dokumen lalu memuat ulang.
  - `ConsentGate` (domain) membungkus aksi tulis: error `consent_required` → `prompt()` → bila setuju, aksi diulang satu kali; bila tidak, `CommunityException(forbidden, code: consent_declined)`. Prompt dibuat di lapisan presentasi oleh `communityConsentGate(context)` (membuka `showCommunityConsent`) dan disuntikkan ke `ComposeCubit`, `CommentThreadCubit`, dan `ChatRoomCubit`; cubit tidak memegang `BuildContext`. `CommunityConsent.prompt` menjamin hanya satu dialog walau beberapa aksi gagal bersamaan. `ChatRoomCubit` melewati gerbang untuk room `support` dan untuk kirim ulang otomatis setelah reconnect.
  - Widget mencari dependensi lewat `CommunityAccountScope.maybeOf` (fallback `RendezvousCommunity.instance`). Tanpa keduanya (mis. tes dengan `CommunityScope` palsu) banner tidak tampil dan gerbang nonaktif, jadi `CommunityDependencies` tidak perlu berubah.
- **Hapus akun:** `deleteMyAccount()` memanggil `delete_my_account` (server mengarsipkan konten, menghapus relasi, mencabut sesi, dan menghapus perangkat push), lalu `PushRegistrar.release()` (tanpa RPC, supaya token dipasang lagi di sesi berikutnya) dan mengakhiri sesi lokal seperti `signOut()` tanpa `unregister_push_device`. Tidak ada exchange ulang otomatis; profil kosong baru dibuat saat panggilan API komunitas berikutnya.
- **Ekspor data:** `exportMyData()` mengubah hasil `export_my_data` menjadi JSON berindentasi UTF-8. Penyimpanan file ada di presentasi (`saveCommunityDataExport`: `file_selector` di desktop, `share_plus` di Android/iOS/web) dan bisa diganti host lewat `exportSaver`. Isi ekspor tidak pernah ditulis ke log.
- **Idempotensi:** composer memakai `client_id` per draf, jadi kirim ulang setelah koneksi putus tidak membuat post ganda. Bagikan post ke chat memakai `client_id` per room.
- **Fitur 1.3.0:** repository baru tidak ditambahkan ke `CommunityDependencies` supaya implementasi host/tes lama tetap valid. Widget mencarinya lewat `CommunityFeatureScope.maybeOf` (fallback `RendezvousCommunity.instance`); bila tidak ada, fitur disembunyikan. Cubit menerima repository baru sebagai parameter opsional (`FeedCubit(bookmarks:, edits:, loader:)`, `CommentThreadCubit(bookmarks:, edits:)`, `ChatRoomCubit(extras:, analytics:)`). Detail perilaku: [features-1.3.md](https://github.com/dayat123123/chat_service_supabase/blob/main/docs/rendezvous-community/features-1.3.md).
- **Konfigurasi klien:** `ClientConfigService` (domain) memegang `ValueNotifier<ClientConfig>` + stream perubahan; `RendezvousCommunity.initialize` memulai timer 5 menit, `AppLifecycleListener` (resume → refresh, hide/pause → flush analitik), dan refresh saat ganti user. `create()` tidak memulai apa pun di latar belakang (tes deterministik). Data source memanggil `errorListener` untuk setiap `CommunityException`; `social_disabled` mematikan UI sosial seketika.
- **Realtime room:** `RoomChannelHub` kini juga mendengar broadcast `reaction` dan `room_state` di `room:<id>` dan meneruskannya sebagai `RoomReaction`/`RoomStateSignal` → `ReactionChanged`/`StockRoomStateChanged`.
- **Generalisasi feed:** `FeedCubit` bisa memakai sumber halaman kustom (`PostPageLoader`) untuk feed hashtag dan bookmark; sumber kustom tidak memuat post tersemat dan tidak menghitung "N post baru". `FeedPostList`/`FeedPostCard` dipakai ulang oleh semua daftar post.
- **Cache offline (1.3.0):**
  - **Penyimpanan (`core/storage`):** `OfflineStore` adalah antarmuka penyimpan baris JSON mentah dari server (room, pesan per room, halaman feed per scope, outbox, meta). Implementasinya `DriftOfflineStore` (drift + SQLite, `CommunityDatabase`, `schemaVersion` = `CommunityDatabase.version`) dan `MemoryOfflineStore`. `platformOfflineStores()` memilih lewat conditional import: file `<application support>/rendezvous_community/<user id>.sqlite` (`NativeDatabase.createInBackground`) di platform `dart:io`, memori di web (tanpa `sqlite3.wasm`). SQLite dibundel paket `sqlite3` lewat build hooks. Naik versi skema membuat ulang tabel cache; tabel outbox dan meta perlu migrasi eksplisit.
  - **Per user:** `OfflineCache` membuka database milik `currentUserId` sesi komunitas. Membuka database user lain menghapus semua database lain (ganti user = hapus). Tanpa sesi (aplikasi dibuka offline) database dibuka hanya bila meta `owner.host_key` sama dengan `hostIdentityKey(token OLT)`: SHA-256 dari `iss`+`sub` JWT (token opaque: hash token utuh). Bila beda, database dihapus. Semua operasi diserialkan dan error penyimpanan hanya dicatat (`Offline cache operation failed`), tidak pernah menggagalkan alur server. `wipe()` dipanggil `signOut()`, `deleteMyAccount()`, dan `clearLocalCache()`.
  - **Tulis (lapisan data):** `ChatRepositoryImpl` dan `FeedRepositoryImpl` menerima `ChatLocalCache`/`FeedLocalCache` opsional dan menulis baris mentah setelah RPC berhasil: halaman pertama `get_my_rooms` (menggantikan seluruhnya, tanpa room `support`), setiap halaman `get_messages`/`p_after`, hasil `send_message`, `leave_room` (hapus room), halaman pertama `get_feed` scope global/following/stock. Halaman pesan direkonsiliasi lewat `reconcileRows`: baris cache dalam rentang halaman (`RowWindow`: setelah pesan tertua halaman bila masih ada halaman berikut, sebelum cursor) yang tidak dikembalikan server dihapus, lalu dipangkas ke `offlineMessageLimit` terbaru per room. Feed saham disimpan untuk 20 scope terakhir.
  - **Baca (domain → presentasi):** `ChatCacheRepository` dan `FeedCacheRepository` (domain) dibaca cubit. `ChatRoomCubit`, `ChatListCubit`, dan `FeedCubit` menampilkan data cache dengan `stale: true`, lalu memuat server; berhasil → state diganti data server (`stale: false`), gagal → data cache tetap tampil (tanpa cache → `failure` seperti sebelumnya). Saat `CommunityConnectivity` kembali online, cubit yang masih `stale` memuat ulang. Chat CS (`CommunityChatRoom(repository: supportChat)`) tidak memakai cache maupun outbox.
  - **Outbox:** `MessageOutbox` (domain, `chat/domain/services`) + `OutboxRepository` (data: baris `outbox` di database yang sama). Hanya pesan teks tanpa lampiran (`OutboxMessage.fromLocal`). `ChatRoomCubit` mengirim lewat `outbox.send(..., guard: consentGate.run)`: pesan disimpan `pending` dulu, lalu dikirim. Keputusan `outboxRetryDelay`: `network`/`unavailable`/`unauthenticated` → tetap `pending` dengan backoff eksponensial (2 detik, maks 1 menit); `slow_mode`/`rate_limited` → langsung `failed` bila dikirim user, dicoba ulang setelah `Retry-After` maksimal 3 kali bila dari latar belakang; error lain → `failed` dengan `CommunityException` (kind, code, message, retryAfter) tersimpan. Urutan per room dijaga: pesan baru menunggu di belakang pesan `pending` yang lebih lama, `flush()` berhenti per room pada pesan yang belum jatuh tempo atau gagal sementara, dan timer dijadwalkan untuk kepala antrean tiap room. Satu `client_id` tidak pernah dikirim paralel (`OutboxBusy`), dan server menolak duplikat lewat `client_id`. Pemicu `flush(force: true)`: sesi user aktif, `CommunityConnectivity` kembali online, aplikasi resume, dan realtime room tersambung ulang. `reset()` (logout, ganti user, `clearLocalCache`) membatalkan timer dan mengabaikan hasil yang datang terlambat. Event `OutboxChanged`/`OutboxDelivered`/`OutboxRemoved` memperbarui pesan lokal di room yang terbuka.
  - **Konektivitas:** `CommunityConnectivity` (core) diisi `SupabaseSocialDataSource.reachabilityListener` (request berhasil atau error dengan respons server → online, error `network` → offline), `ensureSignedIn` yang gagal karena jaringan, dan `ConnectionChanged(connected)` realtime. Saat offline, `probe` (`get_client_config`) diulang 5 detik → 1 menit. Widget menemukannya lewat `CommunityOfflineScope.maybeOf` (fallback `RendezvousCommunity.instance`); tanpa scope tidak ada banner dan cubit berjalan seperti sebelumnya.
- **Fitur `0087`–`0090`:**
  - **Nilai lokal:** `LocalValues` (core/storage) menyimpan JSON kecil per kunci di tabel meta database offline (`OfflineLocalValues`) atau memori (`MemoryLocalValues`, bila `offlineCache: false`). Dipakai `BannerDismissalRepositoryImpl` (`dismissed_banners`) dan `PostDraftStoreImpl` (`post_drafts`: draf + id yang menunggu dihapus di server). Karena di database per user, keduanya ikut terhapus saat logout/ganti user.
  - **Banner:** `ClientConfigModel` membaca `banners`; `CommunityBannersCubit` menggabungkan `ClientConfigService.changes` dan `BannerDismissals` lalu memfilter lewat fungsi murni `visibleBanners` (ditutup, berakhir, belum mulai, prioritas, batas). `CommunityBannerHost` hanya menggambar.
  - **Statistik notifikasi:** `NotificationReporter` (domain) memanggil `NotificationEventRepository` (`report_notification_event`), dedupe per (event, sumber) selama sesi, antrean memori (maks 50) untuk error `network`, `flush()` saat `CommunityConnectivity` kembali online, `reset()` saat ganti user. Pemicu: tap item `CommunityNotificationList` (opened, lalu tapped bila `openCommunityNotification` membuka tujuan) dan `openCommunityPush` (opened, tapped bila tujuan dibuka atau `onOltNotificationTap` dipanggil).
  - **Draf:** `CommunityDrafts` (domain) menggabungkan `PostDraftRepository` (RPC) dan `PostDraftStore` (lokal). `save` menulis lokal dulu, lalu server dengan `serverUpdatedAt` sebagai `p_base_updated_at`; `draft_conflict` → bandingkan `updated_at` server dengan waktu edit lokal, yang lebih baru menang (`DraftSyncStatus.replaced` bila server); `draft_limit`/error lain → `limitReached`/`localOnly`. `list` mencoba ulang penghapusan tertunda, menggabungkan server + lokal (draf lokal yang pernah tersinkron tapi hilang dari server dianggap sudah terbit/dihapus). `ComposeCubit` memantau perubahan teks (`bodyChanged`) dan state (`onChange`) dengan jeda `draftDelay`, menyimpan saat ditutup, dan memakai `clientDraftId` sebagai `client_id` `create_post`.
  - **Kartu saham:** `stockCodesFromJson` membaca lampiran `{"type": "stock"}` di `ChatMessageModel`/`MessageRowModel` (lampiran file tetap lewat `attachmentsFromJson`). Kirim lewat `ChatExtrasRepository.sendStockCards` (bukan `ChatRepository`, supaya kontrak publik lama tidak berubah); pesan kartu saham tidak masuk outbox. `ChatRoomCubit.canSendStockCards` = ada `chatExtras` dan room bukan `support`.
- **Test:** widget bisa diuji tanpa backend dengan membungkusnya di `CommunityScope(dependencies: fake)`.
